# بررسی تخفیف‌های اسنپ‌شاپ با ترب

کالاهای پرتخفیف **snappshop.ir** را پیدا می‌کند و قیمت نهایی‌شان را با قیمت فروشگاه‌های دیگر در **ترب** مقایسه می‌کند تا معلوم شود تخفیف واقعی است یا «قیمت قبل» باد شده بوده.

## اجرا

نیاز: Node.js 20 یا بالاتر (بدون هیچ پکیج اضافه).

```
node src/index.js
```

گزارش در پوشه‌ی `reports/` ساخته می‌شود و خودکار در مرورگر باز می‌شود.

| گزینه | پیش‌فرض | توضیح |
|---|---|---|
| `--min 60` | 80 | حداقل درصد تخفیف اسنپ‌شاپ |
| `--max 100` | 300 | حداکثر تعداد کالایی که در ترب بررسی می‌شود |
| `--torob-limit 10` | 20 | حداکثر تعداد کالای جدیدی که در هر اجرا از ترب پرسیده می‌شود (بقیه در اجرای بعد) |
| `--torob-delay 15` | 8 | فاصله‌ی بین درخواست‌ها به ترب (ثانیه) |
| `--cache-hours 48` | 24 | نتیجه‌ی ترب برای هر کالا تا این مدت دوباره پرسیده نمی‌شود |
| `--no-open` | — | گزارش را باز نکن |

## وضعیت‌ها در گزارش

- **ارزان‌ترین بازار**: قیمت نهایی از همه‌ی فروشگاه‌های ترب کمتر است.
- **ارزان‌تر از بازار**: از میانه‌ی قیمت فروشگاه‌های ترب کمتر است.
- **تخفیف ساختگی**: با وجود تخفیف، از میانه‌ی بازار ارزان‌تر نیست.
- **بررسی نشد**: ترب وسط کار بلاک کرد. بعداً دوباره اجرا کنید؛ کالاهای بررسی‌شده از کش می‌آیند و برنامه از همان‌جا ادامه می‌دهد.
- **تخفیف واقعی** = درصد ارزانی قیمت نهایی نسبت به میانه‌ی قیمت ترب (منفی یعنی گران‌تر).

خود فروشگاه «اسنپ شاپ» در محاسبه‌ی قیمت بازار حساب نمی‌شود.

## نکته‌ها

- snappshop.ir فقط با اینترنت ایران باز می‌شود. در v2rayN پروفایل مسیریابی **«Global + Iran Direct»** باید فعال باشد.
- ترب اگر درخواست زیاد ببیند کپچا نشان می‌دهد. برای همین برنامه در هر اجرا فقط حدود ۲۰ کالای جدید را با فاصله از ترب می‌پرسد و بقیه را به اجرای بعدی می‌سپارد؛ نتیجه‌ها ۲۴ ساعت کش می‌شوند، پس چند اجرا در طول روز همه را پوشش می‌دهد. اگر باز هم کپچا آمد، برنامه همان لحظه متوقف می‌شود؛ `--torob-limit` را کمتر کنید.
- تخفیف واقعی خیلی زیاد (مثلاً بالای ۶۰٪) معمولاً یعنی کالا اصل نیست (تستر یا «طرح») یا با کالای ترب فرق دارد. لینک هر دو در گزارش هست تا دستی چک کنید.

## اجرای خودکار روی GitHub (رایگان)

فایل `.github/workflows/check-deals.yml` برنامه را **هر ساعت** روی سرورهای GitHub اجرا می‌کند و آخرین گزارش را روی GitHub Pages می‌گذارد، مثلاً `https://USERNAME.github.io/REPO/`. کامپیوتر لازم نیست روشن باشد.

راه‌اندازی (یک بار):
1. یک مخزن **عمومی (Public)** در GitHub بسازید و این پوشه را در آن push کنید.
2. در مخزن: **Settings → Pages → Source = GitHub Actions**.
3. در تب **Actions**، workflow «check-deals» را باز کنید و **Run workflow** را بزنید تا اولین گزارش ساخته شود.

نکته‌ها:
- هر اجرا حداکثر ۲۰ کالای جدید را از ترب می‌پرسد؛ چند ساعت طول می‌کشد تا همه‌ی کالاها بررسی شوند.
- اگر مخزن ۶۰ روز هیچ تغییری نداشته باشد، GitHub اجرای ساعتی را متوقف می‌کند و ایمیل می‌دهد؛ با یک کلیک در تب Actions دوباره فعال می‌شود.

## اجرا روی هاست Node.js ایرانی (مثلاً رانفلر)

اسنپ‌شاپ به IP خارجی جواب نمی‌دهد («VPN را خاموش کنید»)، پس هاست باید سرور ایران داشته باشد. GitHub Actions به همین دلیل کار نمی‌کند.

`npm start` حالت سرور را اجرا می‌کند (`src/server.js`):
- آخرین گزارش را روی آدرس سایت نشان می‌دهد؛ وضعیت اجرا در `/status` است.
- هر ساعت خودش بررسی را اجرا می‌کند؛ Cron لازم نیست.
- تنظیمات با متغیر محیطی: `PORT` (پیش‌فرض 3000)، `RUN_EVERY_MIN` (پیش‌فرض 60)، `CHECK_ARGS` (مثلاً `--min 70 --torob-limit 10`).

برنامه هیچ پکیج npm ندارد، پس به اینترنت بین‌الملل روی سرور نیاز ندارد.
